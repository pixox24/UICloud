# 文生图参考图隔离修复设计

## 目标

修复用户从图片编辑或参考图生图切换到文生图后，旧参考图仍可能被发送给模型提供商并导致请求错误进入图片编辑接口的问题。

用户选择保留参考图状态：切换到文生图时，浏览器内存中的参考图继续保留，以便切回图片编辑或参考图生图时恢复；但文生图请求不得包含参考图，服务端也不得因异常输入调用图片编辑接口。

## 模式语义

- `text-to-image`：仅允许走 `/images/generations`。客户端不发送 `referenceImage`，服务端忽略异常携带的参考图。
- `image-edit`：必须提供参考图，并走 `/images/edits`。
- `reference-image`：参考图保持可选；有参考图时走 `/images/edits`，没有参考图时走 `/images/generations`。
- 其他或缺失的模式：返回 `400`，不得调用模型提供商。

## 前端数据流

`referenceImage` 状态不随模式切换、文生图模板载入或文生图历史记录载入而清空。

构造生成请求时按当前模式生成请求体：`text-to-image` 完全省略 `referenceImage` 字段，其他模式才携带当前参考图。这样既保留返回编辑模式时的连续体验，也避免图片数据进入文生图请求。

## 服务端防线

生成接口首先校验 `mode`，再生成传递给 Provider 的规范化参数。对于 `text-to-image`，无论原始请求是否异常携带 `referenceImage`，规范化参数都固定为 `null`。Provider 的接口选择只接收这份规范化参数。

`image-edit` 缺少参考图时返回 `400`。错误必须在调用 Provider 前产生，避免付费请求和含糊的下游错误。

## 验收条件

1. 上传参考图后切换到文生图，生成请求体中不存在 `referenceImage`。
2. 文生图接口即使收到恶意构造的 `referenceImage`，仍只调用 `/images/generations`。
3. 切回图片编辑或参考图生图时，先前的参考图仍可见。
4. 图片编辑缺少参考图时返回 `400`，且不调用 Provider。
5. 无效或缺失模式返回 `400`。
6. 项目生产构建和类型检查通过。

## 范围外事项

本次不修改参考图上传方式、图片大小校验、SSRF 防护、历史记录存储或 Provider 能力模型；这些问题应分别修复。
