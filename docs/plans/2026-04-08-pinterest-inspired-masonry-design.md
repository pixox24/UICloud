# Pinterest 式瀑布流改造方案

## 目标

在保留当前资源库信息密度和交互结构的前提下，将浏览页升级为更接近 Pinterest 节奏的瀑布流布局：

- 图片优先，但不牺牲资产信息可读性
- 卡片宽度与间距稳定，不再完全依赖 CSS columns
- hover 操作更轻、更干净
- 后续可以无痛接入“元信息显示/隐藏总开关”

## 改造范围

- 改造浏览页瀑布流容器
- 精修资源卡片的圆角、阴影、hover 和按钮出现方式
- 轻量调整筛选区的视觉重量

不包含：

- 不复刻 Pinterest 顶部导航
- 不改变当前资产卡片默认信息密度
- 不新增元信息总开关功能

## 方案

新增一个受控 `MasonryBoard` 组件，专门负责：

- 监听容器宽度
- 按宽度计算列数和列间距
- 根据素材比例估算卡片高度
- 用“最短列优先”算法把卡片分发到不同列

`BrowsePage` 继续负责数据、筛选、分页和弹窗状态。
`AssetCard` 只负责展示和交互，不再承担读取列布局的责任。

## 布局规格

- 内容区最大宽度：约 `1680px`
- 页面横向留白：
  - 手机 `12px`
  - 平板 `16px`
  - 桌面 `20px`
- 列间距：
  - 手机 `12px`
  - 平板 `14px`
  - 桌面 `16px`
- 列数规则：
  - `<520px`：1 列
  - `520-767px`：2 列
  - `768-1023px`：3 列
  - `1024-1279px`：4 列
  - `1280-1535px`：5 列
  - `1536-1759px`：6 列
  - `>=1760px`：7 列

## 卡片规格

- 保留名称、格式、文件类型、比例、大小、浏览量
- 圆角提升到更接近画廊卡片的尺度
- 默认边框更轻，减少后台工具感
- hover 改为轻微上浮，不使用明显缩放
- 收藏/下载按钮从右上角淡入并轻微上移

## 风险控制

- 不引入第三方 masonry 依赖，降低维护成本
- 不重做接口与筛选逻辑，避免影响数据层
- 首版不做虚拟滚动，先保持实现简单稳定

## 验证方式

- 浏览页在手机、平板、桌面都能自然分列
- 资源卡片 hover 动作无明显抖动
- 停止使用 CSS columns 后，布局顺序和间距可控
